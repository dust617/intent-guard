# intent-guard · 需求守门

> **A lightweight, always-on requirement guard for coding agents** — aligns on the real goal before acting, decomposes vague asks into verifiable steps, and blocks scope drift. Pure Markdown, zero dependencies.
>
> 帮 Agent 解对问题，而不只是答对答案。

---

## 它解决什么

Agent 有三种典型失败，都不属于「能力不够」，而属于「方向没对齐」：

1. **说的 ≠ 要的** —— 拿到一句话就开始做，做出一个"看起来对"的东西。
2. **做着做着跑偏** —— 顺手加抽象、加依赖、加配置，范围越滚越大，没人叫停。
3. **没人回头审** —— 交付时自评"已完成"，但从没对着验收条件逐条核过。
4. **旧条件被当成还有效** —— 早先的偏好、期限或顺口一提，后续被过度沿用；反过来，仍成立的条件被为了防偏而丢掉，同样算偏。沿用前核三句（还成立吗、适用这次吗、是约束还是只提到），仍适用就照用。不建条件表。

普通 review 查"答案错没错"，本工具查**"问题解对没解对"**。

一个经济账：一次方向性跑偏的返工 = 已做工作作废 + 全上下文重发 + 错误可能已落盘，量级 5k–50k token 加你的时间；一次对齐输出 30–80 token。**拦一次，回本上百次。**

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一段常驻操作纪律（AGENTS.md 六条，其中一条含沿用复核） | 一套框架、数据库或编排引擎 |
| 任务开始的一次判档 + 内部拆解 | 会替你想出领域盲区的专家 |
| 四个检查门 + 按需一次的独立复核 | 每轮都跑的评审 Agent |
| 一个纯 Markdown 技能 | 需要常驻进程的服务 |

## 两层设计（为什么不能只放 skill）

这是本工具唯一的结构性判断：

| 层 | 载体 | 何时生效 | 成本 |
|---|---|---|---|
| 常驻层 | `AGENTS.md` 追加 6 条 | **每次模型调用**（宿主自动注入） | ~230 token/步 |
| 详版层 | `SKILL.md` | 被调用时一次，之后进缓存前缀 | ~2.4k token/任务 |

**纯 SKILL.md 不常驻。** 技能靠描述被"想起来"才加载——想不起来的时候它根本不在上下文里。"任何任务都能辅助到"这个需求，只能靠宿主注入满足，那就是 AGENTS.md。

反过来，**AGENTS.md 也不该写全文**——它是每一步都要重发的。所以：常驻只放"判据"，详版放"方法"。

## 安装

安装器只做两件事：放技能本体、把常驻块写入**你指定的**全局指令文件。已有标记块时就地替换，不再跳过。

⚠️ **默认目标是 `~/.dsh/AGENTS.md`，那是 DSH 的位置。别的宿主读的不是这个文件**——装完只看到 "ok" 不代表生效。

| 宿主 | 全局常驻文件 | 项目级 | 怎么确认真的读到了 |
|---|---|---|---|
| DSH (DeepSeek Harness) | `~/.dsh/AGENTS.md` | `<repo>/AGENTS.md` | 新开会话，看系统提示里有没有「需求守门」 |
| Codex CLI | `$CODEX_HOME/AGENTS.md`（默认 `~/.codex/AGENTS.md`；若存在 `AGENTS.override.md` 则优先读它） | `<repo>/AGENTS.md`，从 git 根向 cwd 串联，上限 32 KiB | `codex --ask-for-approval never "Summarize the current instructions."`，它应当引用该文件内容 |
| Claude Code | `~/.claude/CLAUDE.md` | `<repo>/CLAUDE.md` | `/memory` |

### 一键（Windows）

```powershell
git clone https://github.com/dust617/intent-guard.git
cd intent-guard
powershell -ExecutionPolicy Bypass -File .\install.ps1

# 别的宿主：显式指定目标文件
powershell -ExecutionPolicy Bypass -File .\install.ps1 -AgentsFile "$HOME\.codex\AGENTS.md"
```

### 一键（macOS / Linux）

```bash
git clone https://github.com/dust617/intent-guard.git
cd intent-guard
bash install.sh

AGENTS_FILE=~/.claude/CLAUDE.md bash install.sh    # 别的宿主
```

### 手动

1. `SKILL.md` → `~/.agents/skills/intent-guard/SKILL.md`
2. `AGENTS-snippet.md` → 追加到上表里你那个宿主的文件

安装器是**幂等**的：目标文件里已出现 `intent-guard` 就跳过；改文件前自动备份并打印回滚命令。

**两个坑**：

- 项目里若已有 `AGENTS.md` / `CLAUDE.md`，**项目级规则会覆盖全局**（Codex 是从 git 根向下串联，越靠近 cwd 越靠后、越优先）。常驻块可能被项目规则压掉。
- 装之前先看一眼目标文件里有没有重复或冲突的同类指令，别叠成两层。

### 卸载

```bash
rm -rf ~/.agents/skills/intent-guard
# 从 AGENTS.md 里删掉「需求守门」那一段（安装器会告诉你备份在哪）
```

## 四档分级

判档永远在动手之前，**被触发 ≠ 要走流程**：

| 档 | 判据 | 出声量 |
|---|---|---|
| L0 纯问答 | 查事实 / 不动文件 / 无歧义 | **零行**，直接答 |
| L1 小改 | 改一处、≤3 步 | 答案 + 1 行 `对齐：理解为X【推断】，若错请纠。` |
| L2 中等（默认） | 多步、要动文件、有歧义 | 内部拆解建卡 + **一行拆解预告**；仅阻塞歧义问 ≤3 个 |
| L3 复杂/高风险 | 改架构、动数据或钱、跨系统、不可逆 | 全流程 + 分阶段 + 每阶段一次 delta |

**升级线**：触到 架构 / 成本 / 资源 / 使用方式 / 不可逆 → 直接跳 L3。
**降级**：发现用户只要快答案 → 立刻收声交付。

## 成本（实测）

| 项 | 量 | 何时付 |
|---|---|---|
| 常驻块 | 约 230 token（V4.3 比 V4.2 多约 40 token，来自第四条里的沿用复核） | 每次调用 |
| 技能正文 | 详版，被调用时一次 | 每个任务一次 |
| 输出 | L0 零行 / L1 一行 / L2 一行 / L3 ≤8 行 + 快照 | 每次 |

对照物：一次 `grep` 返回 500–3000 token。**常驻成本低于一次 grep。**

## 触发测试（V4.2 收窄后必须做）

触发词收窄省了无效加载，但可能漏掉没有明显信号词的复杂需求。别凭感觉加回触发词，先测：

取 10～20 个真实任务，记四类：①应触发未触发 ②触发后正确判 L0 退出 ③触发后正确进 L2/L3 ④无谓加载了全文。只针对第①类漏掉的类型补描述，不把高频词加回来。

典型漏触发探针：`帮我把本地文件搜索、文档检索和 Agent 工具调用整合成一个轻量方案`——无"跑偏/拆一下"字样，但明显多步、要取舍、要验收。若这类连续漏，再补一类信号词。

## 设计取舍

这些是迭代出来的结论，不是常识：

- **思考义务 ≠ 输出义务。** 静态只作用于输出层。最坏的失败不是话多，是"因为被要求少说话就少想"。
- **L2 只出一行，不出快照。** 大多数任务是 L2：一行「将拆成 N 步，第 1 步判据是 X」让人能在第一步纠偏；贴 15 行快照而行为不变，就是仪式。调试类任务走「探索档」——不预设完整拆解，但每步仍要可验证。
- **隔离 ≠ 双模型。** 旁观者的独立性来自上下文隔离，不是换个模型。同一个模型 + 看不到你的方案 = 独立性的大部分，成本一次调用。`subagent` 不要用 fork——fork 继承上下文，等于自审。
- **跨会话只记 6 项。** 当前目标 / 已确认约束 / 已做决策及原因 / 未解决问题 / 已验证结果 / 下一步。小任务不落盘，只有跨会话续做或 L3 才写。完整状态库不做，不另开条件表。写的时候按来源内联标清：失效的约束别直接删，标 `[已解除]` 并留证据；偏好标 `[偏好]` 并保留「尽量 / 优先」原词；单次覆盖要连长期默认一起记。摘要写错一条，续做就会照错的版本走。
- **沿用旧条件先复核，不降权一切。** 做法若靠更早的条件，核三句：还成立吗、适用这次吗、是约束还是只提到。三句都过就照用；过期、被更近的说法盖过、仅提及或推断，不得单独定方向。硬约束只在改口或有证据时作废。
- **不做的**：diff 脚本、双 Agent 常态化、打分 metrics。它们都让工具变重，而收益是线性的。

## 已知边界

**大约能给到 80%。**

它能做到：拆得开、说得清"怎么算成了"、该问才问、改口能识别。
它做不到：**想不出你压根没想到的维度。** 它不是领域专家——你说"搭个爬虫"，它知道问站点/反爬/输出/频率（因为写了清单），但不会告诉你"这行其实该考虑合规"。

所以 G4 里留的是**清单**，不是空问：L3 交付前按"合规 / 成本 / 运维"三类过一遍。承认天花板之后，checklist 是唯一还能做的。
