# intent-guard · 需求守门

> **A lightweight, always-on requirement guard for coding agents** — aligns on the real goal before acting, decomposes vague asks into verifiable steps, and blocks scope drift. Pure Markdown, zero dependencies.
>
> 帮 Agent 解对问题，而不只是答对答案。

---

## 它解决什么

Agent 有三种典型失败，都不属于「能力不够」，而属于「方向没对齐」：

1. **说的 ≠ 要的** —— 拿到一句话就开始做，做出一个"看起来对"的东西。
2. **做着做着跑偏** —— 顺手加抽象、加依赖、加配置，范围越滚越大，没人叫停。
3. **没人回头审** —— 交付时自评"已完成"，但从没对着验收条件逐条核过。

普通 review 查"答案错没错"，本工具查**"问题解对没解对"**。

一个经济账：一次方向性跑偏的返工 = 已做工作作废 + 全上下文重发 + 错误可能已落盘，量级 5k–50k token 加你的时间；一次对齐输出 30–80 token。**拦一次，回本上百次。**

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一段常驻操作纪律（AGENTS.md 六行） | 一套框架、数据库或编排引擎 |
| 任务开始的一次判档 + 内部拆解 | 会替你想出领域盲区的专家 |
| 四个检查门 + 按需一次的独立复核 | 每轮都跑的评审 Agent |
| 一个纯 Markdown 技能 | 需要常驻进程的服务 |

## 两层设计（为什么不能只放 skill）

这是本工具唯一的结构性判断：

| 层 | 载体 | 何时生效 | 成本 |
|---|---|---|---|
| 常驻层 | `AGENTS.md` 追加 6 行 | **每次模型调用**（宿主自动注入） | ~185 token/步 |
| 详版层 | `SKILL.md` | 被调用时一次，之后进缓存前缀 | ~2.4k token/任务 |

**纯 SKILL.md 不常驻。** 技能靠描述被"想起来"才加载——想不起来的时候它根本不在上下文里。"任何任务都能辅助到"这个需求，只能靠宿主注入满足，那就是 AGENTS.md。

反过来，**AGENTS.md 也不该写全文**——它是每一步都要重发的。所以：常驻只放"判据"，详版放"方法"。

## 安装

### 一键（Windows）

```powershell
git clone https://github.com/dust617/intent-guard.git
cd intent-guard
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

### 一键（macOS / Linux）

```bash
git clone https://github.com/dust617/intent-guard.git
cd intent-guard
bash install.sh
```

### 手动

1. 把 `SKILL.md` 复制到 `~/.agents/skills/intent-guard/SKILL.md`
2. 把 `AGENTS-snippet.md` 的内容追加到你的全局 `AGENTS.md`（Claude Code 用 `~/.claude/CLAUDE.md`，Codex 用 `~/.codex/AGENTS.md`）

安装器是**幂等**的：已存在则跳过，改 `AGENTS.md` 前会备份。

### 卸载

```bash
rm -rf ~/.agents/skills/intent-guard
# 从 AGENTS.md 里删掉「需求守门」那一段（安装器会告诉你备份在哪）
```

## 四档分级

判档永远在动手之前，**被触发 ≠ 要走流程**：

| 档 | 判据 | 出声量 |
|---|---|---|
| L0 纯问答 | 查事实 / 不动文件 / 无歧义 | **零行**，直接答 |
| L1 小改 | 改一处、≤3 步 | 答案 + 1 行 `对齐：理解为X【推断】，若错请纠。` |
| L2 中等（默认） | 多步、要动文件、有歧义 | 内部拆解建卡；仅阻塞歧义问 ≤3 个 |
| L3 复杂/高风险 | 改架构、动数据或钱、跨系统、不可逆 | 全流程 + 分阶段 + 每阶段一次 delta |

**升级线**：触到 架构 / 成本 / 资源 / 使用方式 / 不可逆 → 直接跳 L3。
**降级**：发现用户只要快答案 → 立刻收声交付。

## 成本（实测）

| 项 | 量 | 何时付 |
|---|---|---|
| 常驻块 | 269 字 ≈ 185 token | 每次调用；50 步会话 ≈ 9k input，缓存命中后约 1/10 |
| 技能正文 | 3532 字 ≈ 2.4k token | 每个任务一次 |
| 输出 | L0 零行 / L1 一行 / L2 默认零行 / L3 ≤8 行 | 每次 |

对照物：一次 `grep` 返回 500–3000 token。**常驻成本低于一次 grep。**

## 设计取舍

这些是迭代出来的结论，不是常识：

- **思考义务 ≠ 输出义务。** 静态只作用于输出层。最坏的失败不是话多，是"因为被要求少说话就少想"。
- **L2 默认不出快照。** 大多数任务是 L2。每轮贴一份 15 行快照，行为却不变，就是仪式。
- **隔离 ≠ 双模型。** 旁观者的独立性来自上下文隔离，不是换个模型。同一个模型 + 看不到你的方案 = 独立性的大部分，成本一次调用。`subagent` 不要用 fork——fork 继承上下文，等于自审。
- **降档，而不是永久闭嘴。** "最近没改变过做法"不等于没用——守门员工作做得好时是无痕的。所以是降一档，不是关掉。
- **不做的**：diff 脚本、双 Agent 常态化、打分 metrics。它们都让工具变重，而收益是线性的。

## 已知边界

**大约能给到 80%。**

它能做到：拆得开、说得清"怎么算成了"、该问才问、改口能识别。
它做不到：**想不出你压根没想到的维度。** 它不是领域专家——你说"搭个爬虫"，它知道问站点/反爬/输出/频率（因为写了清单），但不会告诉你"这行其实该考虑合规"。

所以 G4 里留了一句：**L3 交付前问"有没有我没想到的约束？"** 承认天花板之后，这是唯一还能做的。
